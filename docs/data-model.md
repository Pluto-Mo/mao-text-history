# 数据模型与验收

## 四套资料的登记边界

config/editions.json 按具体书系/版本登记预期卷数：选集四卷加1977第五卷；文稿旧13/新版20；年谱旧3+6/新版9；MIA集10、补卷9、年表1、1968五卷。另以《毛泽东文集》第七卷作为辅助证据，不算用户要求的一套全文。

catalog/volumes.jsonl 每个预期卷都有行。not_acquired 是实际缺卷，不是空正文占位充数。旧版与新版是不同ID；在没有版权页之前，不为官方电子目录推定某个印次。

## 对应关系

- source_id：某个明确的网页或书目信息入口。
- edition_id：具体版次或网站目录所标注的版本，含不确定性。
- I-...：目录中的一条记录；原始题名、定位、来源哈希不改写。
- F-...：一次URL采集的收据，含取得时间、原始字节哈希、长度、HTTP/解析状态。
- M-...：跨目录同题候选组；无方向，不表达先改后。
- E...：人工整理的研究证据；必须带定位和推论边界。

题名归一化只处理Unicode兼容形式、标点、明确的未删节标签与末尾日期；原题名仍保留。归一化后的匹配是候选，不是合并。

## 完整性维度

目录覆盖、网络取得、原文件长期保留、版次核验、映射确认、转载许可分别统计。临时运行器缓存不计长期保留；下载链接不等于下载成功；同题候选不计确认的历史改稿。

## 扩充

先登记来源和版次，再使用 ingest 导入用户合法拥有的文件。纯文本按空行建立段落ID；PDF不盲目OCR。段号不能当作书页码。提取文本单独给 --text-path，书页定位待核对。

失败不会被吞掉：robots禁止、robots访问失败、HTTP失败、空壳页、二进制链接都写入收据或目录状态。工作流运行成功不等于资料齐全，必须读 reports/coverage.json。
